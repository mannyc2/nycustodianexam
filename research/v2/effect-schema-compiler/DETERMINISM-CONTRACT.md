# Determinism contract

## Identity pipeline

```text
current Effect Schema encoded value
  -> project canonical JSON profile
  -> UTF-8 bytes with one trailing LF
  -> SHA-256 lowercase hex prefixed by `sha256:`
```

The production canonical JSON profile must either adopt RFC 8785 exactly or
freeze an equally explicit subset. It must define object-key ordering, number
rendering, Unicode treatment, escaping, unsupported values, and newline policy.
The fixture recursively sorts object keys, preserves array order, uses native JSON
number/string encoding, and appends one LF; that is observed evidence, not yet the
final formal profile.

## Ordered inputs

- normalize author paths to repository-relative `/` form and sort by code-point;
- sort registry records by `(kind, ID, revision)` before output;
- preserve authored semantic list order (steps, options, explanation blocks);
- sort set-like ID arrays explicitly;
- sort diagnostics by the documented stable key;
- never depend on filesystem, object insertion, `Map`, locale collation, or
  concurrent completion order.

## Environment inputs

Release identity includes exact compiler version, gate version, schema family
versions, Effect cohort, canonicalization profile, generator versions, source
revision digests, and authored records. Wall clock, hostname, absolute path,
timezone, locale, username, cache state, and build duration never enter identity.

Publication time is supplied once by the release environment and stored outside
content-object identity. Randomized sessions/print are generated from a separate
versioned PRNG/seed contract, never compiler traversal order.

## Reproducibility tests

Compile the same corpus across:

- reversed filesystem discovery and `Map` insertion order;
- cold/warm caches and clean installs;
- UTC and non-UTC timezones;
- at least two common locales;
- two workspace paths;
- consecutive processes;
- CI and a documented local platform.

Assert identical canonical bytes, object digests, pack roots, and release root.
Diff decoded diagnostics separately for invalid corpora.

## Observed fixture result

Two consecutive rc.111/Bun 1.3.14 probes generated byte-identical copies of all
seven result/artifact JSON files. The hashes are recorded in
`raw-results/REPEAT-HASHES.md`. The probe also compiles each input twice inside
one process and records `deterministic: true`.

## Publication transaction

Outputs are immutable objects. Build into a new staging directory, fsync/close as
appropriate, validate generated Schemas, recompute digests, prove manifest
closure, then atomically promote the manifest/pointer last. Never update current
objects in place. On any failure the old valid release remains active.
