# TAXONOMY.md
Format: `Name | Use | Confused with | Evidence tier/source | Editorial notes`

This taxonomy organizes the original study bank. It is not an official DCS taxonomy and does not imply official weighting.

## Evidence tiers
- **A — Official sample/series evidence:** directly shown or clearly named by controlling DCS guide/announcement.
- **B — Strong entry-level support:** direct custodial occupational/institutional support and consistent with the announced domains.
- **C — Plausible/watchlist:** occupationally adjacent or supported in broader maintenance contexts but not strong enough for automatic entry-bank admission.
- **H — High-level only:** appropriate to High-Level Custodians series/advanced facilities work; excluded from entry sessions.

## Hazard taxonomy
Hazard scenes should be tagged by hazard type and environment. Proposed categories are editorial, not official weighting.

### Slip/trip/fall
- wet floor without appropriate warning/control;
- loose cord/hose across travel path;
- clutter/debris in walkway;
- damaged/unstable floor surface;
- unsafe ladder setup/use;
- standing on unstable object/furniture;
- obstructed stairs/landings.

### Egress/fire
- blocked exit/egress path;
- storage obstructing exit equipment/door;
- unsafe combustible storage near ignition/heat source where source supports;
- inappropriate obstruction of fire equipment.

### Chemical
- unlabeled/mislabeled secondary container;
- incompatible chemicals stored/mixed unsafely;
- chemical in food/drink container;
- missing task-required PPE;
- unsafe splash/exposure setup;
- poor storage/containment where clearly supported.

### Electrical
- damaged cord/plug;
- electrical equipment in unsafe water/wet condition;
- improper cord routing creating trip/damage hazard;
- overloaded/improvised setup only when clearly depicted/source-supported.

### Sharps/broken material
- exposed broken glass/sharp object;
- unsafe hand pickup where tool/PPE should be used;
- improperly contained sharp debris.

### Material handling/storage
- overloaded/unstable cart;
- unstable high stack;
- heavy load carried unsafely/obstructing vision;
- improper use of hand truck/dolly;
- storage creating falling-object hazard.

### Biological/sanitation
- unprotected exposure to bodily-fluid contamination where source supports;
- cross-contamination from inappropriate tool handling;
- unsafe waste handling.

### Machine/tool safety
- damaged equipment;
- missing/defeated guard where visually unambiguous;
- inappropriate tool for task;
- unsafe machine cord/path;
- servicing energized equipment only when concept can be depicted without advanced procedure.

## Illustration QA rules
- No brands/logos/watermarks/official visual language.
- Pure white background for isolated tool assets; black monochrome line art with sparse functional hatching.
- Geometry must be mechanically coherent.
- Distinguishing features must be visible and accurate.
- Avoid impossible handles/joints/blades/jaws.
- Object expressly not to scale.
- Produce canonical 3/4, profile/side, and feature-revealing angle candidates; publish only reviewed assets.
- For pair panels, keep scale/view framing comparable enough to teach the intended distinction without implying equal real-world size.

### Family-specific QA examples
- Pipe wrench: serrated jaws, angled/opening geometry recognizable; not smooth adjustable-wrench jaws.
- Adjustable wrench: smooth parallel adjustable jaws and worm gear; no pipe-wrench tooth profile.
- Flange plunger: extended flange visible beneath cup.
- Cup plunger: simple cup without toilet flange.
- Stepladder: self-supporting A-frame/spreaders.
- Extension ladder: telescoping/overlapping rails; not self-supporting A-frame.
- Crosscut/rip saw: tooth-pattern distinction only if generator/reviewer can render it accurately; otherwise avoid pair question that depends on microscopic tooth details.
- Floor machine/burnisher: do not create a fictitious universal silhouette difference; base distinctions on reviewed real equipment characteristics and broad task context.

## Alt-text metadata modes
Each asset should maintain:
- `neutralAttemptDescription`: enough to communicate image presence/context without naming the answer;
- `fullDescription`: descriptive identification/features for atlas and post-answer use;
- optional Spanish equivalents after professional review.

Do not expose correctness through filenames, accessible names, hidden text, captions, DOM metadata, or image URLs on scored pages.

- security provenance;
- correction history.

## Bank inclusion rule
A node can exist in the atlas/watchlist without automatically being eligible for scored entry-level questions. Scored admission requires:
1. sufficient source basis for the claimed fact;
2. entry-level compatibility;
3. a fair original question that does not rely on ambiguous art;
4. reviewed explanation/distractors;
5. rights/security clearance.

This prevents a broad occupational-tool list from silently becoming an invented exam blueprint.
