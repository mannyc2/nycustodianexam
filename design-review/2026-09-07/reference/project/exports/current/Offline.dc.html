Offline — four deliberate steps, no background magic

The page that owns download, check, turn on and remove. Every state the implementation can reach is drawn here at the width it has to survive, and the two controls the prototype invented — Pause, Cancel — are gone, along with the claim that an interrupted download picks up where it stopped.

Calls I made here

  • The sequence is the page. “How a copy gets onto this device” is a four-step numbered section, not a footnote: download and check, turn on, study, remove. Each step carries the one thing a learner would otherwise assume wrongly — that a partial download is kept, that a checked copy is already in use, that a running session follows the newest copy, that space is freed for you.
  • Nothing to press while it downloads. The downloading row shows bytes and says plainly that leaving or losing the connection starts it again from the beginning. No Pause, no Cancel, no “resumes from there”. The interrupted row is the same sentence, not a distinct “paused” status that implies stored progress.
  • Status is a label, not a border colour. The settled list is one hairline table with a status chip per row, so three copies read as three rows of one thing. Coloured borders are reserved for the states where the colour is the message — failed check, failed update, blocked removal, storage gone.
  • Removal is two screens. Preview names the exact sessions and attempts that depend on the copy and writes nothing; confirm is a separate act. When a paused session needs that exact copy, removal is not offered at all — the row explains what to finish first.
  • No saved copy is an EmptyState; no storage is not. Nothing downloaded yet gets the dashed slot with the one primary action this page exists to perform. A device that refuses to save gets a solid-border notice, because that is unavailable, not absent.

How a copy gets onto this device

Four steps, each one yours to start. This is the whole sequence — there is no background updater.

  1. 1

    Download and check

    The whole file arrives, then its checksum is compared with the published manifest. There is nothing to press while it runs: if the connection drops or you leave, the download starts again from the beginning, and a partly written copy is never kept.

  2. 2

    Turn it on yourself

    A copy that passed its check sits there ready and unused. Turning it on is the only thing that makes it the copy new sessions come from, so a download can never change what you are studying by surprise.

  3. 3

    Study with no connection

    Sets, drills and simulations all run from the copy that is turned on. A session already in progress stays on the copy it started from, even after you turn on a newer one, so questions never change underneath you.

  4. 4

    Remove it when you want the space

    Removal shows you first: how much space you get back, which saved sessions and attempts depend on that copy, and what becomes unreadable. Confirming is a second, separate act, and nothing is ever removed automatically to make room.
