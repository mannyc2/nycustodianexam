Components & design system

Every specimen below is built from the exact V1 token set and the composition rules in COMPONENT_ARCHITECTURE.md. Named compositions replace boolean mode props; states are visibly and textually distinct; nothing here reveals answer-bearing content before commit.

This library is a design reference. docs/ still controls exam facts and allowed scope, and no specimen asserts an official exam length or score.

Path 1

Static semantic HTML

Crawlable, renderer-independent, useful without JavaScript. No React, Effect, or study runtime in the route closure.

Path 2

Bounded React islands

One owner element, lazy-loaded per route, mounted inside one family provider that owns subscription and cleanup.

Compose

No mode flags

No isPractice, isVisual, or showFeedback. Routes pick a named wrapper; structure arrives as children.

Reveal

Commit before reveal

Correctness renders only from a settled durable snapshot. Failure returns to an editable selection and reveals nothing.

Color

One required light scheme. Components consume semantic tokens; they never create family-specific red or green aliases, and every status use also carries text and an icon or shape.

Space, shape, targets

One 0.25rem base with a restrained larger scale. Primary controls hold a 2.75rem block and inline target; nothing non-exempt drops below 1.5rem, and closely placed minimum-size controls keep 0.5rem of separation.

Focus, motion, layers

Native focus is never removed without an equal or stronger replacement. Focused elements receive scroll-margin-block equal to the active sticky-action clearance plus 1rem.

Foundations

DocumentShell and PageHeader

Skip link first, then a site header with identity, three destinations and one utility, one main, then footer. The destinations are Practice, Library and Exams; Settings is the only utility, on the right. Library is a disclosure rather than a route — it opens three collections with a sentence and a count each. From 48rem the row is inline; below it the four become a tab bar and the Library tab opens the same list as a sheet. Nothing in the shell is set to an exam, so nothing in the shell claims to be: there is no exam chip and no chosen-exam state.

Contract notes

The skip link is the first focusable element and becomes visibly prominent on focus. Destination links carry aria-current="page"; the Library summary carries it on no page, because Library is not one. A route that lives under a destination without being it — /review/ under Practice, /offline/ under Settings — takes aria-current="true" and the same filled pill, so the lane is shown without claiming to be the page.

Four things, one tier for three of them. Practice, Library and Exams are the destinations; Settings is the single utility and sits at the right edge with no rule and no siblings. Sources moved to the footer and to the “Where this comes from” line on the records that cite them. Offline moved into Settings and to the download and recovery actions on the pages that need it — the header never carries it.

Library is a native disclosure. summary + panel from 48rem, the same rows as a sheet above the tab bar below it. Rows are a bold destination name and one sentence that includes the count; the closing row is What practice covers. No hover-only opening, no JS requirement, no route named Library.

Active state is the filled pill: --color-selected-surface, bold weight and a filled icon. Icons are decorative and always paired with a text label; in the shipped site they are an inline currentColor sprite, never a web font or background image.

No exam is selected anywhere in the product, so the shell shows no exam chip, no “Choose your exam” control and no pinned-exam state. Practice draws on one question bank for the whole series; that scope is stated on the practice hub (What practice covers) and repeated on each exam page as a reading-only statement.

Connectivity and freshness are stated by .connectivity-notice under the header, not by a nav item: html[data-connectivity="offline"] or html[data-freshness="offline-stale"] shows the band, which names the pinned pack, any withdrawn behavior, and links to the offline page. Network-only actions take [data-network-unavailable] — struck through and inert, never faked.

PageHeader never invents exam facts; breadcrumbs never replace the route heading.

Layout wrappers and prose

Layout-only wrappers, used when no more meaningful HTML element applies. Spacing comes from tokens, never per-page numbers.

Buttons, links, fields

A link navigates; a button changes state or invokes behavior. Native labels, descriptions, errors, and control relationships throughout — single-choice answers always use radio semantics.

Feedback, progress, announcements

Error, warning, success, info, offline, and stale are named variants — not color-only tones. Every one is titled and carries a recovery action.

EmptyState — one shape, three occasions

A dashed slot standing exactly where the list would be. It names what has no items in the learner’s words, says what puts items there, and offers at most two actions. It is for zero records only. Anything that could not be read, was never downloaded or was withdrawn is a Notice or a PageState composition, never this — the dashed border is the promise that nothing is missing.

Contract notes

Heading: what is absent, in the learner’s words, without the word “empty” and without a period. Sentence: what will appear here and what creates it. For a filtered result the scope is in the heading and the first action clears the filter.

Actions: none, one or two. Secondary by default; primary only when the action is the section’s whole purpose and nothing else on the page performs it (choosing an exam). Never a third.

Focus: the heading carries tabindex="-1" and is focused only after the learner’s own filter, search or completion produced the state — never on load (DESIGN_SYSTEM.md behavior matrix, empty row).

Two levels: a section-level EmptyState covers one list on a ready page; the route-level empty of SCREEN_STATES.md (no compatible inventory for the study hub) is a PageState composition that replaces the content, not this.

Selectors: .empty-state, .empty-state-heading, .empty-state-actions, modifiers -filtered, -cleared, -inline, -compact. The shipped EmptyState component of COMPONENT_ARCHITECTURE.md §feedback maps to it one-for-one.

Disclosure, dialog, figure

Native semantics preferred. Dialogs trap focus only while open, name their close control, and restore focus to the invoker.

Contract notes

Selector: ready ↔ filtered empty, and there is no third state: nothing is selected, so there is no pending write and no durable preference. Checker: ready → validating → no-match, ambiguous, or match. Filters use replace-only query state. A cached registry may be offline-stale; an absent one is offline-unavailable — not empty.

Ten lifecycle states

OfflinePackManager

Only an active pack can satisfy a new offline session. A failed update always leaves the previous valid version in place, and removal names the exact sessions it would affect before it does anything.

The download is not user-controlled and not resumable: there is no Pause, no Cancel, and no paused-offline state that keeps part-written bytes. State names below are the record names; learner-facing labels are “Not downloaded”, “Downloading”, “Ready to turn on”, “Turned on”, “Kept for older work”, “Did not pass its check” and “Cannot be removed yet”. Page composition and the removal flow are in Offline.

Foundations — added 2026-09-03

HistoryList — a session list that grows

The hub’s Recent sessions as a list that reads the same at 4 rows and at 40. Every row keeps one template — date, session, outcome, action — so the eye can run down a column. Past six rows the list gains month groups and a footer that counts and expands; past a screen’s worth it gains a filter group by kind. Outcomes are counts, never percentages and never a score.

Contract notes

Thresholds. Up to six sessions: the plain hairline list, no groups, no footer, no filters. Seven or more: month groups, a footer that states “Showing the 6 most recent of N” and expands in place, then collapses again. Twelve or more: a kind filter (all, sets, drills, simulations) as a Tabs row with counts beside each label. The boxed FilterGroup is reserved for a toolbar beside a search field, as on the exam registry; a filter standing alone over a list is always the Tabs row.

Rows never mix kind, scope and outcome into one dashed string. Kind and scope are the name and its sentence; the outcome is a count in its own column; the action is one link, “Resume” for an unfinished session and “Results” otherwise.

The list reads from the attempt events, so it stays available when the progress projection fails — the hub’s read-failed state replaces the header band and the summary sections and leaves this list in place, as the review queue does with its history.

Selectors: .history-list, .history-group-label, .history-row, .history-foot; the kind filter reuses .tabs (role="tablist", aria-selected) with a .filter-count span in each tab.
